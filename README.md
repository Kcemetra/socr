# СтройЖурнал — клиентская версия, предварительная сборка v1

## Что входит

- Только два режима: **М-17** (исходный текст системного промпта и словарь v3), **Общий журнал работ** (5 граф по присланной фотографии). Их таблицы и очереди фото изолированы друг от друга.
- Photo Lab полностью работает в браузере с Blob и Web Worker. Пресеты «бережный» (для уже сжатых фотографий) и приближённый к **sc.py** (медиана 5×5 + Gaussian адаптивный порог 31, C=10, 1-битный PNG).
- PDF из Photo Lab создаётся прямо в браузере без pdf-lib: JPEG встраивается без повторной компрессии, чёрно-белые сканы — через 1-битный Flate. Blob PDF составляется из частей, не формирует Base64-строки. Выходной PDF — набор изображений без текстового слоя.
- Таблица экспортируется в XLSX локально без SheetJS (через ZIP/XML), а кнопка PDF для таблицы открывает нативную печать → «Сохранить как PDF».
- Из настроек доступна только выборочная очистка. Почти незаметная кнопка «·» внизу включает техническую диагностику: статус подключения к серверному ключу, возможность подставить персональный ключ, логи.
- Синхронизации, учётных записей, конструкторов, дополнительных режимов нет.

## Netlify

1. Загрузите **весь корень архива** в приватный Git-репозиторий и подключите репозиторий к Netlify. Простой drag-and-drop папки `public/` не развернёт серверные функции.
2. Сборка не требуется: `netlify.toml` задаёт `publish=public`, каталог функций — `netlify/functions`.
3. Добавьте секрет **`GEMINI_API_KEY`** в Netlify Environment variables **для Functions**. Секрет не прописывайте в файлах `public`.
4. Опционально задайте **`GEMINI_PROXY_URL`** (см. ниже). После изменения переменных деплойте снова.
5. Откройте сайт: через маленькую точку внизу панели очистки можно проверить соединение к AI API.

## Vercel

1. Подключите тот же приватный Git-репозиторий к Vercel. Framework Preset: **Other**. `vercel.json` содержит `outputDirectory=public` и `api/gemini.js` как функцию.
2. Установите переменные **`GEMINI_API_KEY`**, опционально **`GEMINI_PROXY_URL`**, со scope Production / Preview по необходимости.
3. Разверните и проверьте из нужных российских сетей сам HTML, `/api/gemini?check=1` (через диагностику), а затем реальное распознавание.
4. Если регион функции не может обращаться к Google AI API, испытайте другой регион/прокси. На бесплатном Vercel время вызова функции ограничено; очень долгие запросы к модели могут завершаться таймаутом.

## Прокси только для запросов к Gemini

Серверные переменные (НЕ в `client-config.js`):

```text
GEMINI_API_KEY=ваш_секретный_ключ
# HTTP CONNECT (или HTTPS proxy):
GEMINI_PROXY_URL=http://username:password@host:3128
# или SOCKS5: DNS через прокси
GEMINI_PROXY_URL=socks5h://username:password@host:1080
# без авторизации:
GEMINI_PROXY_URL=http://host:3128
```

Прокси разрешён только в `server/gemini.js`, его используют запросы к `generativelanguage.googleapis.com`. **Статические файлы, Photo Lab, PDF и IndexedDB никогда не проксируются**. Если пароль содержит `@`, `#`, `:`, `/`, `?` — закодируйте эти символы с помощью URL percent-encoding. Поддержка SOCKS5 требует устанавливаемой NPM-зависимости `socks-proxy-agent` (входит в `package.json`).

## Модель и локальное хранение

Модель для всех клиентов задаётся в `public/client-config.js` (НЕ помещать туда API-ключ!). По умолчанию `gemini-3.5-flash-lite`, как в исходном v3. Если на вашем аккаунте Google такого model ID нет, замените ID на реально поддерживаемый и переопубликуйте сайт. Для serverless-платформ модель указывается клиентом в запросе к API.

Состояние: ключ браузера `stroy_client_v1_state`, а фотографии IndexedDB `StroyOcrPhotosDB` с полем `modeId`. Не используйте одновременно этот сайт и v3/v4 **под одним и тем же origin**: хранилище IndexedDB у них общее и форматы могут пересекаться. Перед развёртыванием на ранее используемый домен сделайте бэкап нужных данных.

## Ограничения и незавершённая проверка

- Эта сборка — **предварительный прототип**, в чате не проводился полноценный браузерный тест с реальным Gemini API, 100 реальными фотографиями или обоими production-хостингами.
- Vercel ограничивает тело запроса/ответа функции 4,5 МБ, а Netlify буферизованный payload — 6 МБ; фронтенд предупреждает при запросе более 4 МиБ. Большие входные фотографии отправляются в OCR в уменьшенном варианте.
- `sc.py` использует OpenCV `INTER_AREA`, а JS использует Canvas scaling. Алгоритм медианы/порога близок, но результаты **не обязаны совпадать пиксель-в-пиксель**. Сам профиль sc.py работает медленнее бережного. Для входных фото менее 1 МБ выбирайте «Бережная» и «Без уменьшения».
- При 100 очень крупных исходных JPEG итоговый PDF всё равно может быть большим (соответствует входу). Предварительно обработайте их, чтобы снизить объём.
- Кнопка PDF для таблицы вызывает системный диалог печати, а не немедленное скачивание файла.
- Дев-переключатель ключа не является системой авторизации, скрытая кнопка не обеспечивает безопасности. Защита тестового API по просьбе пользователя не добавлялась.
- Два режима имеют разные таблицы; промпт Общего журнала работ ещё требует тестирования на нескольких страницах, чтобы правильно обрабатывать длинные описания.

## Быстрый smoke-test после деплоя

1. Проверить, что в боковом меню ровно три пункта.
2. Загрузить 1 страницу в М-17 и 1 в Общий журнал работ, сменить вкладку, убедиться, что фото не пересекаются.
3. В Photo Lab прогнать 1 исходное и 1 уже сжатое фото на обоих пресетах.
4. Сформировать PDF сначала из 3, потом из 30 и 100 страниц; открыть в обычной PDF-программе.
5. Проверить XLSX, печать таблицы и «Передать в журнал».
6. Через точку внизу настроек проверить наличие ключа и реальную доступность модели.
